# テニスラケット診断アプリ 機能仕様書

**バージョン:** 1.0
**最終更新:** 2026-09-15

---

## 1. 概要

### 1.1 目的

テニスプレイヤーが自分に最適なラケットを選べるよう、9問の質問で回答者のプロフィールを分析し、ラケットデータベース（40本）から上位3本を推薦するWebアプリ。

### 1.2 技術スタック

| 区分 | 採用技術 |
|------|---------|
| フレームワーク | Next.js 16 (App Router) |
| 言語 | TypeScript 5 |
| スタイリング | Tailwind CSS 4 |
| UIコンポーネント | shadcn/ui |
| チャート | Recharts |
| テスト | Vitest |
| ホスティング想定 | Vercel (SSG) |

### 1.3 画面構成

| URL | 種別 | 役割 |
|-----|------|------|
| `/` | クライアントサイド | 9問の質問フォーム |
| `/result?a=...` | SSG + 動的OGP | 診断結果表示 |

## 2. データモデル

### 2.1 ラケットスペック (`RacketSpec`)

```typescript
{
  id: string;           // 一意識別子 (例: "yonex-ezone-100-2024")
  brand: string;        // ブランド名
  series: string;       // シリーズ名（多様性フィルタに使用）
  model: string;        // モデル名
  year: number;

  weight: number;       // フレーム重量 (g)
  balance: number;      // バランスポイント (mm)
  swingWeight: number;  // スイングウェイト
  headSize: number;     // フェイスサイズ (平方インチ)
  ra: number;           // フレーム硬度 (RA値, 50–75)
  beamWidth: number;    // ビーム幅 (mm)
  pattern: '16x19' | '16x20' | '18x20' | 'other'; // ストリングパターン

  price: number;        // 定価 (円)
  imageUrl: string;
  affiliateUrl: {
    rakuten: string;
    amazon: string;
  };
  overrides?: Partial<AxisScores>; // 手動スコア上書き（任意）
}
```

### 2.2 6軸スコア (`AxisScores`)

全軸 0〜100 のスケール。

| 軸 | 意味 |
|----|------|
| `power` | ボールの飛び |
| `control` | コントロール性 |
| `spin` | スピン性能 |
| `maneuverability` | 操作性（軽快さ） |
| `comfort` | 快適性（衝撃吸収） |
| `volley` | ボレー適性 |

### 2.3 ユーザー回答 (`Answers`)

```typescript
{
  q1: 'beginner' | 'beginnerIntermediate' | 'intermediate' | 'advanced';
  q2: 'baseline' | 'allround' | 'net';
  q3: 'compact' | 'standard' | 'full';
  q4: ('noPower' | 'tooMuchPower' | 'noSpin' | 'lateBall' | 'armPain')[];  // 最大2選択
  q5: 'none' | 'sometimes' | 'painful';
  q6: 'under275' | '275to290' | '290to305' | 'over305' | 'unknown';
  q7: 'poly' | 'nylon' | 'unknown';
  q8: 20000 | 30000 | 40000 | null;  // null = 上限なし
  q9: string[];  // ブランド名（空 = 指定なし）
}
```

### 2.4 プレイヤーターゲット (`Target`)

質問回答を変換したプレイヤープロフィール。

```typescript
{
  ideal: AxisScores;              // 理想の6軸スコア
  weight: Record<Axis, number>;   // 各軸の重要度（合計 = 6.0）
  filters: HardFilter[];          // ハードフィルタ（絶対条件）
}
```

## 3. 診断アルゴリズム

### 3.1 軸スコア算出 (`axes.ts`)

ラケットの物理スペックを0〜100に正規化して6軸スコアを計算する。

**正規化関数:**

```
norm(v) = (v - min) / (max - min) × 100   ← 高いほど高スコア
inv(v)  = 100 - norm(v)                    ← 低いほど高スコア
```

**各軸の計算式:**

| 軸 | 計算式 |
|----|-------|
| power | `0.35×norm(swingWeight) + 0.25×norm(headSize) + 0.25×norm(ra) + 0.15×norm(beamWidth)` |
| control | `0.35×inv(headSize) + 0.30×inv(ra) + 0.20×patternControl + 0.15×inv(beamWidth)` |
| spin | `0.40×patternSpin + 0.30×norm(headSize) + 0.30×norm(swingWeight)` |
| maneuverability | `0.45×inv(weight) + 0.40×inv(swingWeight) + 0.15×inv(balance)` |
| comfort | `0.45×inv(ra) + 0.30×inv(beamWidth) + 0.25×norm(weight)` |
| volley | `0.35×inv(balance) + 0.35×maneuverability + 0.30×norm(weight)` |

> **注:** comfort だけは重量が高いほどスコアが上がる（重いラケットほど振動を吸収するため）。

**ストリングパターンボーナス:**

| パターン | patternControl | patternSpin |
|---------|---------------|------------|
| 18×20 | 100 | 20 |
| 16×20 | 65 | 55 |
| 16×19 | 35 | 100 |
| other | 50 | 50 |

### 3.2 ターゲット生成 (`target.ts`)

質問の回答から `Target`（理想スコア・重みづけ・ハードフィルタ）を生成する。

#### 処理順序

1. **Q1（レベル）** → `BASE_IDEAL[level]`, `BASE_WEIGHT[level]` でベース値を設定
2. **Q2（プレースタイル）** → `ideal += PLAY_STYLE_IDEAL_DELTA[q2]`, `weight *= PLAY_STYLE_WEIGHT_MUL[q2]`
3. **Q3（スイング幅）** → 同様にデルタ・乗数適用
4. **Q4（悩み）** → 1問目はフル適用、2問目は重みのみ `×1.5` で適用
5. **Q5（肘の状態）** → デルタ・乗数適用 ＋ `painful` の場合はハードフィルタを追加
6. **Q6（現在のラケット重量）** → 重量ハードフィルタを追加（`unknown` の場合はレベルとスイング幅から推定）
7. **Q7（ストリングの種類）** → デルタ適用
8. **Q8（予算）** → 価格ハードフィルタを追加
9. **Q9（ブランド）** → ブランドフィルタを追加（選択時）
10. **重みを正規化** → 合計が 6.0 になるようスケール
11. **ideal を 0〜100 にクランプ**

#### 肘ハードフィルタ（Q5 = `painful`）

| 条件 | 値 |
|------|----|
| RA値 | ≤ 66 |
| ビーム幅 | ≤ 24mm |
| フレーム重量 | ≥ 285g |

> **設計意図:** 軽いラケットは振動を吸収しにくいため、テニス肘には逆効果。重量下限は物理的根拠に基づく。

### 3.3 スコアリング (`score.ts`)

#### ペナルティ計算

```
penalty = Σ( weight[axis] × gap[axis] )  for each axis

gap[axis] =
  if axis in [comfort, maneuverability, volley]:
    max(0, ideal[axis] - racket[axis])   ← 下回った場合のみペナルティ
  else:
    |ideal[axis] - racket[axis]|         ← 両方向ペナルティ

score = max(0, 100 - penalty / 6.0)
```

> **設計意図:** comfort・操作性・ボレーは「多すぎる」ことはない（一方向ペナルティ）。
> power・control・spin は高すぎても低すぎてもNG（双方向ペナルティ）。

#### フィルタリングと結果選択

1. ハードフィルタ（予算以外）を適用
2. 候補が0件 → 次の予算帯を提案
3. 候補をスコア降順でソート
4. 同一シリーズは最大1本に限定（多様性フィルタ）
5. 上位3本を返す

## 4. 質問仕様

| Q | 問 | 選択肢 | 複数選択 |
|---|----|--------|---------|
| Q1 | プレーヤーレベル | 初級 / 初中級 / 中級 / 上級 | 不可 |
| Q2 | プレースタイル | ベースライン / オールラウンド / ネットプレー | 不可 |
| Q3 | スイング幅 | コンパクト / スタンダード / フルスイング | 不可 |
| Q4 | 現在の悩み | パワー不足 / 飛びすぎ / スピン不足 / 打点が遅れる / 腕が痛い | 最大2選択 |
| Q5 | 肘の状態 | 問題なし / 時々痛い / 常に痛い | 不可 |
| Q6 | 現在使用ラケット重量 | 275g未満 / 275〜290g / 290〜305g / 305g超 / わからない | 不可 |
| Q7 | 現在のストリング | ポリ系 / ナイロン系 / わからない | 不可 |
| Q8 | 予算 | 2万円 / 3万円 / 4万円 / 上限なし | 不可 |
| Q9 | ブランド希望 | Yonex / Wilson / Babolat / Head / Dunlop / Technifibre / Prince | 複数可・不問も可 |

## 5. 結果表示

### 5.1 推薦カード（最大3枚）

各カードに表示する情報:

- ランクバッジ（1位 / 2位 / 3位）
- ラケット画像
- モデル名・ブランド・年式
- 定価
- 推薦理由（テンプレートベース）
- 楽天 / Amazon アフィリエイトリンク
- Q5=`painful` の場合: 医療免責注記

### 5.2 推薦理由テンプレート

重みが最も高い2軸を使った自然文を自動生成する。

例: 「パワーを重視している方に向けて、ボールが飛びやすく○○を選びました。スピン面でも優れているため、スピンのかかりの向上にもつながります。」

### 5.3 レーダーチャート

Recharts を使い、**ユーザー理想値**と**推薦ラケットスコア**を6軸レーダーで重ねて表示。

### 5.4 比較テーブル

推薦3本の6軸スコアとマッチスコアをテーブルで比較。

## 6. URL エンコード / 共有機能

### 6.1 フォーマット

```
/result?a={q1}-{q2}-{q3}-{q4_bits}-{q5}-{q6}-{q7}-{q8_idx}-{q9_bits}
```

- **q4_bits:** Q4の複数選択をビットマスクで表現（最大5項目 → 5bit）
- **q9_bits:** Q9の複数選択をビットマスクで表現（最大7ブランド → 7bit）
- **q8_idx:** 予算を 0〜3 のインデックスに変換
- 旧フォーマット（8パラメータ）との後方互換性あり

### 6.2 用途

- SNS 共有
- 結果ページの静的生成（OGP 動的タイトル）

## 7. SEO / コンプライアンス

### 7.1 OGP

- 結果ページのタイトル・説明文を推薦1位のラケット名で動的生成

### 7.2 アフィリエイト表示（景品表示法対応）

- ページ上部に「本ページはアフィリエイト広告を含みます」バナーを常時表示
- アフィリエイトリンク近傍に「PR」表記

### 7.3 医療免責

- Q5=`painful` 選択者には結果ページに免責文を表示（医師への相談を推奨）

### 7.4 robots.txt / sitemap

- `robots.ts`: クロール制御
- `sitemap.ts`: 動的サイトマップ生成

## 8. テスト仕様

### 8.1 テストケース一覧

| # | シナリオ | 検証内容 |
|---|---------|---------|
| 1 | 初級 / ベースライン / パワー不足 | 大フェイスラケットが推薦される |
| 2 | 上級 / パワー不足 | 薄フレーム・小フェイス・18×20 が推薦される |
| 3 | パワー計算の一貫性 | スペックとスコアの相関確認 |
| 4 | 肘フィルタ（`painful`） | RA≤66・ビーム幅≤24・重量≥285 を強制 |
| 5 | 2問の悩み | 第2問の重み×1.5 が正しく適用される |
| 6 | ネット / ボレー専門 | ボレー軸重視ラケットが上位に来る |
| 7 | 予算オーバーライド | 該当なし時に次の予算帯を提案 |
| 8 | エッジケース | 極端な組み合わせでクラッシュしない |
| 9 | 決定性 | 同一入力 → 同一出力（乱数なし） |
| 10 | シリーズ多様性 | 上位3本が異なるシリーズから選ばれる |

### 8.2 実行コマンド

```bash
npx vitest run
```
