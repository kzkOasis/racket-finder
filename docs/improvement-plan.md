# racket-finder 改善指示書

- この文書は Claude Code に読み込ませる改善指示書である。現状の設計は `docs/design.md` を参照
- ゴール: **最初の1件の成約（楽天アフィリエイト報酬）**。そのために「購入ボタンを押す機会を増やす」「シェアされたときに目立つ」「流入と成約を計測できる」の3点を優先する
- タスクは優先度順（P0 → P1 → P2）に進める。各タスクの完了時に `npm test` と `npm run lint` を通し、1タスク1コミットにする
- Next.js 16 は学習データと API が異なる場合がある。実装前に `node_modules/next/dist/docs/` の該当ページを読むこと

## 守ること（当初仕様書から引き継ぐ）

- 6軸スコアは式で算出し、JSONに手書きしない
- 快適性・操作性・ボレーの片側ペナルティを両側に変えない
- 肘「痛みがある」の重量下限 285g を消さない
- ~~予算オーバー時に条件を勝手に緩めない~~ → 予算の質問そのものを廃止したため、このルールは役目を終えた
- シェアURL（`?a=`）の既存の並び順を変えない。選択肢は末尾に追加する

## P0: 収益に直結する（最優先）

### P0-1. 結果を3本にする（多様化）

**理由**: 今は1本しか出ないため、購入ボタンが1つしかない。「1位は高いけど2位なら買える」という人を逃している。

**作業**
- `score.ts` に `diversify(scored: ScoredRacket[]): ScoredRacket[]` を追加し、`runDiagnosis` の `top` をその結果にする
  1. 1位 = 最高スコア
  2. 2位 = 1位と別シリーズのうち、`comfort + maneuverability` が1位より高いものの中で最高スコア
  3. 3位 = 1位・2位と別シリーズのうち、`control + spin` が1位より高いものの中で最高スコア
  4. 2位・3位の条件に合うものがない場合は、別シリーズの中でスコア順に埋める。候補が3本未満なら、あるだけ返す（水増ししない）
- `ResultPageContent.tsx` で3本分の `ResultCard` を `rank={1|2|3}` で並べる
- レーダーチャートに3本を重ねる（色は3色を定数化）
- 未使用の `ComparisonTable` を、カードの下に表示する
- 予算オーバー時の文言を「¥◯◯まで広げると候補が見つかります」に直す（`¥` と `円` の重複を解消）

**完了条件**
- テスト10が「3本返り、シリーズが重複しない」ことを実際に検証するよう書き換えて通る
- 2位・3位の選び方のテストを追加する

### P0-2. 商品画像を楽天の商品画像に差し替える

**理由**: 現在の画像の多くは tennis-warehouse.com（米国の小売店）の透かし入り画像を直接読み込んでいる。無断利用にあたるおそれがあり、先方が外部からの読み込みを止めると画像が一斉に消える。

**作業**
- 楽天ウェブサービスでアプリIDを発行し、楽天市場商品検索APIで各ラケットを検索して `mediumImageUrls` と商品ページの `affiliateUrl`（アフィリエイトIDを渡すと返る）を取得する
- 取得は**ビルド前に手動で実行するスクリプト**とする（`scripts/fetch-rakuten.mts`）。結果は `rackets.json` の `imageUrl` と `affiliateUrl.rakuten` に書き戻す。本番のページ表示のたびにAPIを呼ばない
- 検索結果が意図しない商品（ガット・ケースなど）にならないよう、キーワードに「硬式 ラケット」を付け、価格の下限（例: 10,000円）で絞る。取得結果は目で確認してからコミットする
- APIキー・アフィリエイトIDは `.env.local` に置き、コミットしない
- API を使うので、フッターに楽天ウェブサービスのクレジット表記を入れる（文言とリンクは楽天ウェブサービスの規約に従う）
- 画像が取れなかった機種は、現状どおり「ブランド名＋モデル名」のプレースホルダーを出す
- APIのエンドポイントとパラメータは最新の楽天ウェブサービスのドキュメントで確認すること
- **2026年の仕様変更**: エンドポイントが `openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/<version>` に移行し、`applicationId` に加えて `accessKey` が必須になった

**完了条件**
- `rackets.json` に tennis-warehouse.com の URL が残っていない
- 画像の `alt` は「ブランド名 モデル名」にする

### P0-3. シェアされたときに目立つようにする

**理由**: 集客の主な入口はXでのシェア。今はシェア画像がなく、ボタンもXに直接投稿できない。

**作業**
1. `layout.tsx` に `metadataBase: new URL(process.env.NEXT_PUBLIC_SITE_URL ?? 'https://racket-finder-two.vercel.app')` を追加する
2. 動的OGP画像を作る
   - `opengraph-image.tsx` はクエリ文字列を受け取れないため、**Route Handler `src/app/api/og/route.tsx`** で `ImageResponse`（`next/og`）を返す。`?a=` を受け取り、診断を実行して1位のブランド名・モデル名を描画する（1200×630）
   - `ImageResponse` の標準フォントは日本語を含まない。Google Fonts の Noto Sans JP を `text=` パラメータで必要な文字だけ取得し、`fonts` に渡す
   - 回答が不正な場合は、サイト共通の画像を返す
   - トップページ用の静的な共通画像も用意する（`src/app/opengraph-image.tsx` でよい）
3. `result/page.tsx` の `generateMetadata` で `openGraph.images` に `/api/og?a=...` を設定し、X のカードを `summary_large_image` にする
4. 結果画面に「Xでポスト」ボタンを追加する
   - `https://x.com/intent/post?text=...&url=...` を新しいタブで開く
   - 文面例:「私に合うテニスラケットは {ブランド} {モデル} でした🎾 #テニスラケット診断」
   - 既存の「この結果をシェアする」（Web Share / URLコピー）も残す

**完了条件**
- X の投稿画面に結果URLを貼ると、大きい画像カードにモデル名が表示される（公開後に実機で確認）

### P0-4. すぐ直せる表記の修正

- `layout.tsx` の説明文「8問」を「9問」に直す（`description` / `openGraph` / `twitter` の3か所）
- `<html lang="en">` を `lang="ja"` にする
- ブランド表記の「Technifibre」は正しくは「Tecnifibre」。**表示ラベルだけ**直す（`BRANDS` の並び順は変えない。`rackets.json` の `brand` と揃えて両方直すこと）

### P0-5. 計測を入れる

**理由**: どこで離脱しているか分からないと、次に何を直すべきか決められない。

**作業**
- `@vercel/analytics` を入れ、`layout.tsx` に `<Analytics />` を置く（ページビューの計測。Vercel のダッシュボードで Web Analytics を有効にする）
- 楽天のリンクのクリック数と成約は、楽天アフィリエイトの管理画面のレポートで確認する（コード変更は不要）
- 見る指標: トップの閲覧数 → 結果ページの閲覧数（完走率）→ 楽天リンクのクリック数 → 成約

## P1: 信頼性と使いやすさ

### P1-1. プライバシーポリシー・運営者情報のページ

- `/privacy` を作る。内容: アフィリエイトプログラムへの参加（楽天アフィリエイト）、アクセス解析の利用、免責事項、問い合わせ先
- 全ページのフッターから、`/privacy` と楽天ウェブサービスのクレジットへリンクする

### P1-2. 不正なURLで落ちないようにする ✅ 実装済み

**実際の症状**（調査結果）: HTTPは500ではなく200だが、範囲外のインデックス（例: `?a=9-9-9-0-9-9-9-9`）だと `buildTarget` の中で `TypeError` になり、画面には Next.js の**英語のエラー画面「This page couldn't load」**が出ていた。診断へ戻る導線がなく、流入を捨てていた。非数値・要素数不足は既存のガードで日本語の案内が出ていた。

**やったこと**
- `decodeAnswers` で各パーツを検証し、不正なら `null` を返す（数値以外・範囲外・負数・要素数・ビット幅超過）
- 予期しないエラーの保険として `src/app/result/error.tsx`（日本語の案内と診断への導線）を追加
- テストを追加（範囲外・非数値・空文字・要素数・負数・ビット幅・旧形式の互換）

### P1-3. トップページに説明を入れる ✅ 実装済み

**理由**: 今のトップはいきなり質問1から始まり、検索から来た人には何のサイトか分からない。検索エンジンが読めるテキストもほぼない。

**作業**
- ~~質問1の前に、短いスタート画面を置く~~ → `step 0` として実装
- ~~その下に「ラケット選びの3つのポイント」程度の短い解説を置く~~ → 実装
- 導入・解説はサーバーコンポーネントで描画して初期HTMLに入れている（クライアントに置くと検索エンジンに読ませにくい）。初期HTMLの本文は実質0文字 → 約900文字になった

### P1-4. 理由文をラケットの強みと合わせる ✅ 実装済み

**現状**: 理由文はユーザーの重みだけで作っていて、ラケット側のスコアを見ていない。そのため、快適性が低いラケットにも「フレームが柔らかく衝撃が少なく」と書くことがある。

**作業**
- 重み上位の軸のうち、そのラケットのスコアが候補内で上位（例: 60以上）の軸を優先して文にする。該当がなければ、ラケット自身のいちばん高い軸で文を作る
- 3本それぞれで文面が変わるようにする

- 報酬の対象はリンクをクリックした後の購入で、**紹介したラケット以外の商品が買われても対象になる**（対象期間などの条件は楽天アフィリエイトの規約で確認すること）
